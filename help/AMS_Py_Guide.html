History and foreword

AMS_Py is the sibling application to STARpaleomag_Py — same paleomagnetism laboratory (Institut de Géologie de Rennes), same author (P. Roperch), same Fortran/AWE heritage, and the same low-level graphics primitives (plott, symbol, newpen…) that STARpaleomag_Py's own plotlib.py already ported — reused here rather than re-derived, since both applications trace back to the same Absoft AWE codebase.

Where STARpaleomag_Py processes directions and paleointensity, AMS_Py is dedicated to anisotropy of magnetic susceptibility (AMS) — the 6- or 15-position kappabridge measurement protocol, the Jelinek (1978) tensorial mean and its confidence ellipses, and the standard shape diagrams (Flinn, T–P′) used to characterize a rock's magnetic fabric. It is a port of AMS_OSX_AWE, the Fortran/Qt5 application that handled this side of the lab's work, following the same rebuild approach as STARpaleomag_Py: Python 3, Tkinter for the interface, Matplotlib for every plot, and PmagPy wherever a MagIC-standard statistic is involved (the Hext 1963 F-test, in particular — see Calcul).

Open source. The source code is available on GitHub alongside STARpaleomag_Py. As with its sibling application, researchers and students wishing to use or modify this program are encouraged to do so through Claude.

Data formats: .pmagani and .prmag

AMS_Py's own native format is .pmagani — and it is shared byte-for-byte with STARpaleomag_Py: the two applications read and write the exact same column schema, so a .pmagani file can carry STARpaleomag_Py's A0/F0 tensors (TRM/ARM anisotropy, from its own 6-position Anisotropy dialog) and AMS_Py's own N0 tensors (bulk susceptibility, from a kappabridge) side by side for the same specimen, and either application can read a row the other one wrote. A specimen's site and sample name, needed for MagIC export, are not duplicated into .pmagani — they are looked up from a companion .prmag file of the same base name (STARpaleomag_Py's own working format), opened once via Open File .prmag….

Why not keep site/sample in .pmagani too? .pmagani and .prmag are already paired by filename (same base name, same folder) — repeating site/sample in both would just be a second copy to go stale relative to the other. A specimen with no matching .prmag entry is still usable in AMS_Py; only the MagIC export step needs the pairing, and it says so explicitly when a specimen's site/sample is missing rather than exporting a guess.

Legacy data comes from two other places: an old-style .ANI file (no column headers, the format both applications used before .pmagani existed — still readable directly, or convertible once via Import legacy .ANI to .pmagani…), and a plain-text AGICO Kappabridge report (a .asc file, straight off the instrument's own SUSAR/Anisoft software) — converted directly to .pmagani by convert ASC to .pmagani…, tagged N0.

Typical session flow

Most sessions follow the same sequence:

  1. LoadAMS Files → Open File .prmag… (locates the companion .pmagani automatically)
  2. SelectAMS data → Select measurements…
  3. ComputeCalcul → Tensorial mean
  4. VisualizeGraphics → Stereographique / Anisotropy parameters
  5. ExportAMS Files → Export to Magic / Export site means to Magic…
Current orientation (Sample / In situ / Tilt cor.). Every tensor is reoriented live according to the choice made in AMS data — raw specimen frame, drilling-corrected, or drilling-plus-bedding-corrected. Data is always stored in the specimen frame in .pmagani; changing the orientation changes only what's displayed and what a fresh Tensorial mean computes from, not what's on disk.
Keyboard shortcuts. Shown in parentheses after some labels, e.g. Cmd+E. Always Cmd or Cmd+Ctrl — never Ctrl alone, to avoid conflicting with the input field's own editing shortcuts. Matches STARpaleomag_Py's own combinations for the orientation shortcuts (Cmd+Ctrl+A/B/T) so switching between the two applications doesn't mean relearning them.

AMS Files files

Load data, convert legacy formats, export to MagIC.

Open File .pmagani… Cmd+O
Loads a .pmagani file directly (or an old-style .ANI, read as-is). If opened this way rather than via Open File .prmag…, AMS_Py also looks for a companion .prmag of the same base name and loads it automatically, so site/sample lookups work either way round.
Open File .prmag…
Loads a .prmag file (STARpaleomag_Py's own format) and automatically locates and loads its companion .pmagani. This is the recommended way in — it guarantees site/sample metadata (used by Stereographic site, and by STARpaleomag_Py's own unified MagIC export once this .pmagani is picked up there) is available from the start. If neither a .pmagani nor an old .ANI companion exists yet, an empty .pmagani (header only) is created and made the active file automatically — ready for Archive ASC into .pmagani… without an extra file dialog.
List File .pmagani
Prints every raw tensor currently loaded — the six components as stored, one line per measurement, not the eigen-decomposition (that's List measurements below).
Import legacy .ANI to .pmagani…
Converts an old-style .ANI file (list-directed Fortran output, no column headers) to the current tab-separated .pmagani format with a proper header row. A one-time upgrade — the old file is untouched.
Create prmag & pmagani from legacy .ANI…
Builds a .prmag straight from an old .ANI's own core-orientation columns (cin/caz/dip/str) — useful when the original field notes are lost but an old .ANI with orientation data survives. Deduplicates by specimen id first: a real ATRM specimen repeats once per jackknife variant (A0/A+/A-/A1/B1…B6, up to 15 rows) in a legacy .ANI, all sharing the same orientation — only the first is kept. Also converts the same .ANI into the companion .pmagani in the same step (the tensor data is already there, no reason to leave it empty), unless one already exists under that name (left untouched rather than overwritten).
Create prmag & pmagani from .asc AGICO file… new
Same idea, straight from the kappabridge's own .asc report instead of an already-converted .ANI — same cin/caz/dip/str columns (same AGICO orientation-convention transform and warnings as Archive ASC into .pmagani… below, see its own entry), same specimen-id deduplication. The companion .pmagani is built via Archive ASC into .pmagani…'s own logic, so — unlike the .ANI version above — an existing .pmagani under that name is not left untouched: only the specimens genuinely new to it are added, incrementally, same as archiving into it directly.
Archive ASC into .pmagani…
Reads an AGICO Kappabridge .asc report (the instrument's own SUSAR/Anisoft software output) and appends only the specimens not already present (matched on specimen id + code2 + applied field — see below) into an existing .pmagani, rather than regenerating the whole file: a lab's .asc grows over weeks as new specimens are measured, and re-running this on the same growing file must never wipe out site means or export markers already curated in the meantime. If a .pmagani is already the active file, it archives straight into it with no extra dialog — and afterward, any newly-archived specimen with no matching entry in the companion .prmag is flagged (a mismatched file or a typo, most likely). New tensors are tagged code2=N0; orientation (cin/caz/dip/str) is transformed from the report's own AGICO P1/P2/P3/P4 convention (see the callout below, not just carried through as-is), and Hext statistics (err.%, F, F12, F23) and the applied field (A/m, field_Am column) are carried straight through whenever the report includes them — the MFK2 kappabridge in particular can measure one specimen at several field strengths, each kept as its own row rather than overwriting the previous measurement.
Verify the orientation convention. Every specimen block in a real .asc declares its own AGICO orientation parameters (REMA6W manual §12.2's P1–P4 — arrow direction, which angle counts as inclination, which compass direction counts as azimuth, dip-direction vs. strike/dip for the bedding). This command reads that declaration per specimen and transforms cin/caz/str accordingly, warning explicitly (listed in the result, "issue(s) found") whenever a value can't be fully verified (P1 ≠ 12) or isn't recognized at all (P3 = 9, block skipped rather than risking a silently wrong azimuth). P1 ≠ 12 specifically leaves cin/caz/str/dip at n.d (0.0) rather than a computed value — this app's whole pipeline (in-situ/tilt-corrected views, Correction sondage…) assumes P1 = 12, so a value computed under any other P1 would be silently wrong, not just unverified; the raw tensor itself is never affected and is always imported. A plain "no warning" only means every declared value matched what this parser has actually been verified against — it doesn't replace checking a file from an unfamiliar source (a different lab, an older acquisition, a kappabridge software update) against the manual by hand. This is exactly the kind of mismatch that has caused real errors before (a past Utrecht-to-MagIC export). Note this only matters for a specimen with no matching .prmag entry — orientation for a matched one is always overwritten by the companion .prmag's own (already-verified) values instead, see Open File .prmag….
Mark selection for MagIC export…
Takes whatever is currently built up in AMS data's selection and/or Mean Results' working list, and treats it as the complete desired export set for the active .pmagani: every specimen/mean in that set is marked export=Y, every other row in the same file export=N — a replace, not an add. STARpaleomag_Py's own unified MagIC export then skips any row marked export=N when it reads this same file, so curating a subset here is enough to control what gets exported, without a separate intermediate file.

AMS data selection & orientation

Build a working selection of measurements, and choose the coordinate frame everything else computes in.

Select measurements Cmd+E
Adds matching measurements to the current selection by specimen name (wildcards accepted). Accumulates on top of whatever is already selected rather than replacing it — the same behavior as the original Fortran selmes, which only ever grows the list; only init list to zero clears it. This lets you build up a selection spanning several specimens (or several separate picks of the same specimen) across multiple calls.
List measurements Cmd+L
Lists the current selection's principal axes (k1/k2/k3, dec/inc) and shape parameters (L/F/P/P′/T) in the currently chosen orientation — not the raw tensor components (that's List File .pmagani). The PmagPy Hext F-test verdict line, shown once per specimen group, is highlighted in bold green (satisfactory) or bold red (not satisfactory) — the same convention applies anywhere else this verdict is printed.
List measurements with depth not ported
Not yet implemented — planned to use the depth field already present in specimen characteristics.
init list to zero Cmd+I
Clears the current selection. The only thing that does — see Select measurements above.
Delete lines Cmd+D
Removes one or more measurements from the current selection by line number, after listing them.
Sample coordinates Cmd+Ctrl+A
Raw specimen frame — no reorientation applied. Every tensor computation and plot uses whichever of these three is active.
In situ coordinates Cmd+Ctrl+B
Drilling-orientation correction applied (cin/caz), no bedding-tilt correction. Default at startup.
Tilt corrected coordinates Cmd+Ctrl+T
Drilling correction plus bedding-tilt correction (dip/str).

Mean Results working list of tensorial means

A separate in-memory list of already-computed site-mean tensors (self.mean_results) — distinct from the raw-measurement selection in AMS data, and from the site-mean section of a .pmagani file on disk. These commands move results between the two.

Select results
Loads mean tensors already saved in the currently open .pmagani's site-mean section into the working list. Filtered to the exact orientation currently active in AMS data — Sample/In situ/Tilt cor. results are never mixed together in one selection, since only In situ and Tilt corrected share a common (geographic) reference frame in principle, and even that turned out not to be a safe assumption to build a filter on.
List results
Lists every tensor currently in the working list — id, site (when the id resolves to one), orientation, and the full Jelinek statistics box for each.
init list results
Clears the working list, after confirmation.
delete result
Removes one entry from the working list by number, after listing them.
Liste results file
Read-only: lists the site-mean section already saved in the currently open .pmagani, without touching the working list. Use Select results instead to actually load some of them in.
save results in File
Writes the entire working list into the currently open .pmagani's site-mean section. Always pauses first for a Y/n confirmation, whatever the tensor's own Hext significance — the point is to make sure the numbers get looked at before being written, not to gate saving on the F-test verdict.

Calcul tensor statistics

Compute a tensorial mean, correct a paleomagnetic direction for anisotropy, and combine or compare tensors.

Tensorial mean Cmd+M
Jelinek (1978) tensorial mean of the current selection (at least 3 measurements, in the currently active orientation): eigenvalues, dec/inc of each principal axis, and their 95% confidence ellipses. Shape parameters (L/F/P/P′/T) verified byte-for-byte against a real MagIC contribution's own magicams.txt.
Isotropic tensors are excluded from the mean automatically (classified via the same Fortran thresholds, kept exact including their asymmetry) — self.mean_results's reported n is the count actually used, which can be less than the selection size.
Mean susceptibility
Arithmetic and geometric mean (plus geometric standard deviation) of the bulk susceptibility across the selection — needs at least 3 measurements. Uses the k2 eigenvalue of the de-normalized tensor rather than the scalar s directly, matching the original routine's own convention.
Fisher 3 axes not ported
Not yet implemented.
ellipses Bootstrap
The original Fortran routine (bootams) is an empty stub too, so this is new work rather than a port: non-parametric bootstrap (parametric optional) on the current selection, fitting a Kent distribution (zeta/eta) to the resampled eigenvectors via PmagPy's own pmag.s_boot/sbootpars — a genuinely different method from the Jelinek ellipse computed by Tensorial mean, not a replacement for it. Needs at least 3 measurements; prompts for the number of draws and whether to plot the resampled cloud, the fitted ellipse, or both.
Inverse correction
Corrects a paleomagnetic direction for anisotropy using the first tensor in the current selection — a direct port of corpaldir, which the original Fortran's own prompt already warns about ("attention prend le premier tenseur de la liste").
Substraction of tensors
Subtracts one tensor from another for exactly two measurements in the current selection. The list variant (several pairs at once, soustractliste in the original Fortran) is not yet ported.

Graphics plots

Stereographic projections, shape diagrams, and SVG export.

Stereographique Cmd+Ctrl+S
Principal axes (k1/k2/k3) of the raw selection and/or already-computed mean tensors, prompted the same way as Anisotropy parameters below (data/results/both). Mean-result symbols are drawn twice the size of individual measurements to tell them apart, with their 95% confidence ellipses — the part that exits the lower hemisphere is drawn dashed in the upper hemisphere, folded back onto the same azimuth rather than projected outside the primitive circle.
Stereographic sample
Walks the current selection specimen by specimen (grouped by consecutive id): for each one, its measurement list (with the A0 comment), its stereogram, then its Flinn/P′–T shape diagram — the same "Return for next sample" rhythm as the original Fortran.
parametres projection
Stereographic vs. equal-area (Lambert) projection, and whether negative inclinations are inverted onto the primitive circle rather than plotted with a distinct open symbol. The custom projection radius the original Fortran also prompts for is not asked here — it's a confirmed real bug in the source (rdim is silently ignored, always 15.0, whatever's typed), not worth reproducing.
Anisotropy parameters Cmd+Ctrl+P
Flinn diagram and T–P′ diagram together on one page — a single menu entry replacing what used to be two separate Fortran ones. Source is prompted the same way as Stereographique: raw data (0), already-computed mean results (1), or both (2). Specimen ids are annotated next to points only below 15 measurements, to avoid clutter.
Susceptibility / anisotropy degree new
One point per raw measurement in the current selection (no data/results/both prompt — a mean tensor has no individual bulk susceptibility to plot). Two stacked panels, both against P′ (Jelinek's corrected anisotropy degree) on Y: bottom panel (Real) plots susceptibility on a normal log scale; top panel (Imaginary) plots |susceptibility| on a log scale with the X axis reversed — negative (imaginary) values grow toward the left.
Im vs Re susceptibility new
One point per specimen in the current selection that has both a Real and an Imaginary susceptibility measurement (scalar, orientation-independent — no orientation prompt). X axis is split at a vertical divider: negative (imaginary) K to the left, |K| on a reversed log scale; positive K to the right, on a normal log scale — independent scales either side. Y (Real susceptibility) is log-scaled and shared across both halves.
Export SVG…
Exports whichever plot is currently displayed to an SVG file — matplotlib writes it directly from the Figure, no separate export code needed. Works mid-loop, same as in STARpaleomag_Py: nothing stops you from using it while a batch dialog (Stereographic sample, for instance) is paused waiting for your next input — the menu stays fully clickable.

.pmagani file format reference

Two sections in the same file — specimen tensors, then site-mean tensors — each with its own column schema, exactly the way STARpaleomag_Py's own .pmagres separates specimen results from site means. An older .pmagani written before the site-mean section existed has no marker for it at all, and is read entirely as the specimen section, unchanged.

Specimen section

Marked by the header line #specimen tensor results. One row per tensor variant — code2 distinguishes A0/F0 (STARpaleomag_Py, TRM/ARM anisotropy) from N0 (AMS_Py, bulk susceptibility) and the 14 STARpaleomag_Py jackknife variants (A+/A-/A1…B6, read-only diagnostics as far as AMS_Py is concerned). Same column-for-column schema on both applications: specimen, code2, etape, k11, k22, k33, k12, k23, k13, s(SI*1e-5), n_positions, sigma, ftest, ftest12, ftest23, quality, field_Am, export, info — raw (not trace-normalized) tensor components, in the specimen frame. field_Am is the applied field (A/m) recorded by Archive ASC into .pmagani… when the report gives it (the MFK2 kappabridge can measure the same specimen at several field strengths); export (Y/N) is set by Mark selection for MagIC export…. A file written before either column existed is still read correctly — both default to "not set"/Y.

Site mean section

Marked by the header line #site mean tensor results, always at the end of the file — a new specimen row is inserted before this marker if it already exists, never appended after it, so the two sections never get interleaved. Deliberately a different schema from the specimen section, not raw tensor components: principal axes (k1≥k2≥k3, Jelinek convention) with dec/inc and 95% confidence half-angles per axis, plus the shape parameters.

ColumnMeaning
site, code2, nsite name, tensor type, number of specimens actually used in the mean (isotropic tensors excluded)
k1, k2, k3principal eigenvalues, decreasing
dec1, inc1 … dec3, inc3declination/inclination of each principal axis
alpha1_1, alpha2_1 …95% confidence half-angles (major/minor) around each axis, Jelinek (1978)
P, T, L, F, Pprimshape parameters of the mean tensor
tilt_correctionorientation this mean was computed in, MagIC-style code (-1/0/100 = Sample/In situ/Tilt corrected) — a dedicated column; older files that only ever noted this in free-text info are still read (falls back to "unknown")
exportY/N — set by Mark selection for MagIC export…, same meaning as the specimen section's own export column
infofree text note
Written and read by both applications. AMS_Py can read a site mean STARpaleomag_Py wrote and vice versa — the format was extended once, in the shared schema, rather than each application inventing its own site-mean file.
